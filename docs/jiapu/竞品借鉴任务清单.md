# 竞品借鉴任务清单

来源：2026-11-04 对国际在线平台、桌面软件、自托管开源、中国大陆商业产品与机构库的调研。
完整对比见同目录 `族谱工具竞品对比.xlsx`（产品总览 / 能力打分 / 维度天花板 / 可抄清单 / 数据来源）。

排序原则：先做「判据能当天写出来」的，再做需要新模块的，最后做需要外部采购或决策的。
每项都必须带**能红的验收判据**——只有正控没有负控的判据不算判据。

## P0（本周可做，合计约 3 人日）

### 1. 拿 relationship.js 当差分测试的裁判

- **做什么**：把开源库 `mumuy/relationship`（MIT，只算称谓不算服制）的关系链↔称谓表灌进测试，与我们 `server-core/kinship.js:459` 的 `describeRelation` 做全量交叉比对。
- **落点**：新增 `test/kinship-oracle.test.mjs`；不引入运行时依赖，只在测试里用一份离线导出的对照表。
- **验收判据**：
  - 正控：差异逐条归类为「我们错 / 它错 / 地域差异」三类，且三类都有实例（若一类为空，说明对照没跑起来）。
  - 负控：故意把 `describeRelation` 里「姑父」的推导改坏，判据必须红。
  - 区域模式（默认 / 北方 / 粤语）各跑一轮，**必须暴露我们写死的北方口径**（如「姥爷 vs 外公」「爷爷 vs 阿爷」）。
- **风险**：它不算服制，不能拿它验 `mourningGrade`（`server-core/kinship.js:336` 一带）；混用会把「它本来就不管」当成我们的错。
- **工作量**：1 人日

### 2. 修谱校对报告（学云码宗谱的智能查错）

- **做什么**：把 `server-core/health.js` 的规则集扩成一份可导出的送审报告：父子同名、子大于父、世代倒挂、生卒矛盾、存疑无出处、年号/农历写法异常。
- **落点**：`server-core/health.js:8` `auditFamilyData` 加规则；报告导出挂到 `js/views/statistics.js` 的体检区或新视图。
- **验收判据**：
  - 正控：500 人样例中植入 12 处已知错误，必须检出 12 处且定位到 memberId。
  - 负控：干净样例必须 0 报（否则规则在误伤）。
  - 新规则一律用 `info` 级（参考 `server-core/health.js:39` 的 certainty-disputed 口径），**不许把 warning 数量刷上去**，否则体检分会教会用户「别标存疑」。
- **工作量**：2 人日

## P1（下个迭代）

### 3. 分享链接的隐私粒度从「整人」降到「单字段」

- **来源**：webtrees 的五级隐私 + 事实级 RESN 限制。
- **现状**：`server.js:1226` `shareMember` 按「在世/已故」整档取舍，`server.js:1200` `SHARE_MEMBER_FIELDS` 是整人级白名单。
- **做什么**：创建链接时提供三档预设（仅谱文 / 标准 / 完整），其中「标准」允许把生卒年单独放开、把住址类字段继续收口。
- **验收判据**：同一在世成员，「卒年」在分享页可见而「电话/住址」不可见；反向用例（完整档）两者都可见。负控：把预设档位写死成一档时，这条必须红。
- **风险**：档位说明要写给不懂技术的族里老人看，默认档绝不能放松。
- **工作量**：2 人日

### 4. 支系审定人（学 WikiTree 的 Honor Code 监护制）

- **现状**：`js/core/collaboration.js:52` `PROVER_WRITABLE_FIELDS` 是字段级白名单，但没有「谁对哪一支系负责」。
- **做什么**：在角色模型上叠一个「支系审定人」属性：一个房/支系指定一名审定人，未经其审定，该支系不能定稿/不能进印谱流程。
- **验收判据**：非审定人提交定稿必须 403；审定人变更后其先前的审定自动失效。
- **风险**：**千万不要另起第二套权限系统**。必须与现有字段级白名单合并设计，否则两套规则互相掩盖，出现「A 拦住了 B 又放行」。
- **工作量**：4 人日

### 5. 一致性检查器：同一人多条互相矛盾的记载（学 Gramps）

- **做什么**：`auditFamilyData` 增加「同一人存在两个不同生年/卒年且各自带出处」的矛盾检测，并给出「哪两条在打架」的可点定位。
- **验收判据**：植入两条矛盾记载必须报出且引用两条出处 id；单条记载必须 0 报。
- **工作量**：1 人日（与第 2 项同批做更省）

### 6. 逐页释文 + 双人校对投票（学 FamilySearch 众包索引）

- **现状**：`js/views/documents.js:402` 已有 `transcription`，`:243` 甚至已经有 `proofreadNote` 字段——**底子在了，缺的是「第二个人」和「分歧队列」**。
- **做什么**：同一页允许两名成员各交一份释文；不一致的页进入争议队列，不直接覆盖。
- **验收判据**：两人释文不同 ⇒ 该页出现在争议队列且保留两份；同一人重复提交 ⇒ 不产生第二票。
- **风险**：需要账号间互斥（同一个人不能给自己投票），否则「多数一致」是假的。
- **工作量**：6 人日

## P2（需要决策或外部条件）

### 7. 纸屏同源的排版管线（差距最大的一项）

- **来源**：印刷行业现行做法（竖排右翻、筒子页、版心标谱名/卷次/页码、齐栏、宣纸线装）+ 族谱网的矢量印刷稿导出。
- **现状**：`js/io/lineage-print.js:83` 只有 `@page { size: A4 portrait; margin: 15mm }`，靠浏览器打印；跨页吊线图会断裂，页码与目录不同步。
- **做什么**：服务端无头 Chrome `printToPDF` 出「矢量 + 文本层」PDF；先解决三件事——卷次、页码、版心。
- **验收判据**：导出的 PDF 能搜到文字（不是整页图）；目录页码与实际页一一对应；跨页吊线图不断列。
- **风险**：浏览器 `@page` 与 `:left/:right` 不可靠，别指望纯 CSS 解决分页；这条与第 8 条（四式同源）耦合，单独做意义有限。
- **工作量**：8 人日

### 8. 四式同源切换 + 目录页码互通（学族谱网 / 百家有谱）

- **做什么**：欧式五世一表 / 苏式吊线 / 宝塔 / 牒记行传共用同一套卷次与页码模型，切换版式不重排页码。
- **前置**：第 7 项先定下页码模型。
- **工作量**：5 人日

### 9. OIDC 单点登录（学 Gramps Web）

- **做什么**：`handleAuth` 增加可选 OIDC 分支（Keycloak / Authentik / Authelia），未配置时行为完全不变。
- **验收判据**：测试实例登录后 session 与现有 token 等价；现有登录/限流套件全绿。
- **风险**：多一条认证链路就多一个攻击面，默认必须关闭。
- **工作量**：3 人日

### 10. 对齐 T/CAS 692-2023 团标

- **事实**：`现行`，发布与实施均为 2023-02-27，适用范围原文含「数字化族谱、纸质族谱的**应用软件和数据加工处理**」，规范性引用含 GB 18030（中文编码字符集）、GB/T 7156（文献保密等级）、GB/T 18894（电子文件归档）。
- **做什么**：**先取正式文本**（非免费公开），再逐条比对数据交换、保密等级、编码、导出格式，出一份「已符合 / 待改 / 不适用」三态说明。
- **验收判据**：说明文档存在且每条结论指向具体条款与我们的具体代码位置。
- **风险**：拿到文本前**不能对外声称符合**；起草方与《中华族谱大典》编辑委员会深度绑定，商业色彩自行判断。
- **工作量**：2 人日 + 获取文本

## 明确不做

- **自研老谱 OCR**：13 家横评结论是纯自动化基本不可用，且避讳缺笔/异体字本身是校勘证据，规范化等于毁证据。要做也只做「AI 预填 + 人工确认」，不做自动结论。
- **记录库 / DNA 匹配**：65B 记录、27M DNA 是买不来的护城河，与「家族自持」定位不同赛道。
- **共享世界树**：与「数据在自己服务器上」的产品承诺直接冲突；要学的是它的**监护制**（第 4 项），不是它的共树模型。

本轮先补的是「能力打分」里分差最大的两项，不是照抄清单顺序：

| 能力 | 之前 | 现在 | 依据 |

| 印刷交付 | 2 | **3** | 分卷 + 卷次/页码进版心 + A4 固定页 + 目录页码互通 + 纸面溢出测量 + 生成物零内联脚本；`test/print-layout.test.mjs` 23 项 |

顺带修掉一个已在线上但没人发现的缺陷：打印窗口是 `window.open("") + document.write`，会继承应用 CSP（`script-src 'self'`），**内联脚本与 `onclick` 全被拦**——原来那个「打印」按钮在正式环境里点不动。现在生成物零脚本，打印由打开方调用 `win.print()`，溢出测量也移到能跑代码的一侧。

仍未做（仍是 P2 第 7 项的后半）：无头 `printToPDF` 服务端出件、3mm 出血、对开筒子页页序、跨页吊线图不断列。
