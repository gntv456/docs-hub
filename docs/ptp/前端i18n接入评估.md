# 前端 i18n 接入评估（vue-i18n）

> 结论：**建议独立批次实施**。框架接线本身约半天，但字符串抽取面 318 个文件，
> 与「能跑就行」的功能开发冲突；未完成整批抽取前接入只增加复杂度不产生价值。

## 现状盘点（2026-08 实测）

| 项 | 数值 |
|---|---|
| `.vue` 组件文件 | 169 |
| 含中文字符串的文件（.vue/.ts） | **318** |
| 仅 views 目录中文行 | ~2134 |
| 现有 locale 基础设施 | 无（`ElConfigProvider`/locale 均未使用） |
| 目标框架 | vue-i18n v11（兼容 Vue 3.5）+ element-plus 对应 locale 包 |

## 分阶段实施方案

1. **框架接线（~0.5 天）**
   - `npm i vue-i18n`；`src/i18n/index.ts` 创建实例（`legacy: false` 组合式 API 模式）。
   - `main.ts` 挂载；`App.vue` 用 `<ElConfigProvider :locale="elLocale">` 联动 element-plus 内置文案。
   - `src/i18n/locales/zh-CN.ts`（现有文案基线）+ `en-US.ts`（骨架）。

2. **首批抽取（~2 天，建议范围）**：全局壳层 + 高频页
   - 导航/侧边栏、登录页、设置页、通用操作按钮（保存/取消/删除/刷新）、错误提示统一走 `t()`。
   - 抽取约定：key 按 `页.区块.元素` 命名（`login.form.username`）；插值用 `{name}` 占位。

3. **长尾迁移（持续）**：新增代码一律 `t()`；存量页面按模块逐步迁移，
   配 `eslint-plugin-vue-i18n` 的 `no-raw-text` 规则防回潮（warning 起步，稳定后转 error）。

## 风险

- **量大易回归**：318 文件手工改写易漏；建议用脚本粗抽（正则抓模板文本节点）+ 人工复核，
  分 PR 按模块合并，每批跑 `npm test` + 冒烟。
- **后端错误消息是中文**：`t()` 只覆盖前端静态文案；后端返回的 `error.message` 需后端
  错误码化 + 前端按码翻译（独立工作量，见 `internal/api/v1/auth.go` 错误语义现状）。
- **移动端不同步**：Flutter 端有自己的 `intl` 体系，两端口径需对齐（可后置）。

## 判定

纳入独立迭代排期，不并入当前修复批次——避免「接了框架但只迁了 5% 字符串」的半成品状态。
