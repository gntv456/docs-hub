# 设备监控模块

「NAS 服务器」主菜单提供三类设备的**完整真实监控管理**：服务器、NAS、摄像头，并支持摄像头 **RTSP 视频预览**。严格复用项目既有的 Model + Oper(AES) + Chain/Service + Handler + guarded 路由模式，新增依赖全部纯 Go 无 CGO。

## 功能覆盖

| 模块 | 能力 |
|---|---|
| **服务器** | 本机（gopsutil：CPU/内存/磁盘/网络/负载/温度/进程/运行时长）+ 远程 SSH 采集（/proc 解析）+ Agent 主动上报 |
| **NAS** | Agent 主动上报（飞牛、绿联等国产 NAS 推荐）、群晖 Synology API、TrueNAS/FreeNAS REST API、通用 SNMP fallback（负载/内存/存储表） |
| **摄像头** | ONVIF 设备发现/信息/码流地址（自写 SOAP + WS-Security）、RTSP 探活、**RTSP 视频预览（H.264 + H.265）** |
| **告警** | CPU/内存/磁盘/温度阈值 + 离线告警，状态转换去重，复用通知链（bark/tg/webhook） |
| **时序** | MetricSnapshot 历史快照 + 自动清理（默认保留 30 天） |

### 采集器分发矩阵

`Registry` 按 `(type, protocol)` 注册（`ResolveProtocol` 在 protocol 为空时按 type/host 推断）：

| type | protocol | 采集器 | 凭据（AES 加密） |
|---|---|---|---|
| host | local | HostCollector（gopsutil，忽略 Host/凭据） | 无 |
| host | ssh | SSHCollector | username + password |
| host / nas | agent | AgentWSHub 主动上报（绕过 Collector） | 每设备独立 secret |
| nas | local | HostCollector（gopsutil，支持 bind mount 磁盘路径） | 无 |
| nas | api | NASCollector → synology / truenas | username + password（TrueNAS 用 API Token） |
| nas | snmp | NASCollector → gosnmp | username = community |
| camera | onvif | CameraCollector（SOAP，自动回填 RTSPURL） | username + password |
| camera | rtsp | CameraCollector（gortsplib 探活）；预览支持 H.264/H.265 | rtsp_url |

凭据由 `Oper.Credentials` 解密注入 Collector，Collector 不持久化明文。

### 采集调度

`Service.Run` 单 ticker（10s）扫表 → 到点（`LastCheckedAt + IntervalSec ≤ now`）的 target 并发采集（per-target `context.WithTimeout` + panic 恢复）→ `RecordSnapshot`（对比上次快照算网络速率）→ `Alerter.Evaluate`。target 增删/interval 改无需动调度（与 `ws.Broadcaster.Run` 同模式）。每日 3 点清理 30 天前快照。

### RTSP→WebSocket 代理

浏览器不能直播 RTSP。`RTSPProxy` 用 gortsplib 拉流 → 解 H.264/H.265 → annexB 帧 → gorilla/websocket 转发，前端 jessibuca(wasm) 解码。一路摄像头单路拉流、多观众复用（refCount + 30s 保活窗口）；全局观众上限（默认 8，防资源耗尽）；鉴权复用 ws.go 的 `?token=<jwt>` + CheckOrigin 白名单。jessibuca 为 GPL-3.0，**不随仓库/镜像分发**；由后端在首次使用时自动获取落盘到 `DataDir/jessibuca`（见 [assets.go](backend/internal/web/assets.go)），用户无需任何操作。

## 小米 / 米家摄像机接入

小米（含新米家系列）走 **P2P + 云转发**，码流加密，**官方不提供 RTSP / ONVIF**。因此无法像海康、大华那样直接填 IP 接入，必须先用外部方案把码流「翻译」出来。本系统的设备表单在选择摄像头协议时会直接显示这段指引（`CameraBridgeHint.vue`）。

### 方案 A：Miloco + Micam + go2rtc（推荐，支持新款）

官方 Miloco 负责从米家云拉流，Micam 转推给 go2rtc，后者对外提供标准 RTSP。

```bash
mkdir -p /opt/micam && cd /opt/micam
wget https://raw.githubusercontent.com/miiot/micam/refs/heads/main/docker-compose.yml
docker compose up -d
```

1. 浏览器打开 `https://<miloco 地址>:8000`（**自签证书，需手动信任**）
2. 设置 Miloco 密码，绑定小米账号，确认能看到该摄像机画面
3. 编辑 `docker-compose.yml` 增加流名，在 `micam` 服务里配 `.env`：

   ```bash
   MILOCO_PASSWORD=<Miloco 密码的 md5 小写>
   CAMERA_ID=<摄像机 DID，在 Miloco 页面 F12 网络请求里看>
   RTSP_URL=rtsp://<go2rtc 地址>:8554/<stream 名>
   VIDEO_CODEC=hevc   # 默认高清流；摄像头输出 H.264 时改为 h264
   ```

4. 取出 `rtsp://<go2rtc 地址>:8554/<stream 名>`，在 PTPatronus 里：**添加设备 → 类型「摄像头」→ 协议「RTSP 直连」→ 粘贴地址 → 探活**

> Micam 默认取**高清流 + 音频流**。本项目只解视频，音频轨会被忽略；如需声音请在上游用 go2rtc 转封装时单独处理。

### 方案 B：yi-hack 第三方固件（老款 Yi 系列最省事）

Hi3518 / Hi3518ev200 芯片的老款小米/小微 Yi 系列可刷 [yi-hack](https://github.com/alienatedsec/yi-hack-v5) v4/v5 固件，**自带 RTSP + ONVIF + SSH**。刷完后协议直接选「ONVIF」，只填 IP 与账号密码，厂商/型号/固件信息与码流地址均由系统自动发现。

### 编码说明

Micam 默认输出 **H.265（HEVC）**。本系统的 RTSP 代理与 HLS 封装均已同时支持 H.264 与 H.265（见 `video_codec.go`）：

- 选轨时 **H.264 优先、H.265 兜底** —— 同一路流同时提供两种编码时优先落 H.264，兼顾前端解码器兼容性
- WebSocket 预览的 `ready` 信令会**上报实际编码**（`{"type":"ready","codec":"h265"}`），前端据此选解码器
- HLS（移动端 media_kit 链路）按编码分派 `WriteH264` / `WriteH265`

> H.265 解码能力随 jessibuca 版本而定。本项目锁定 **v3.3.28**，其 wasm 内含 `HEVC decoder`，播放器会从 annexB NAL 头自动判别 H.264/H.265，前端无需分派配置。

### 预览解码器：用户零操作

摄像头实时预览需要 jessibuca 的 wasm 解码器（约 1.4 MB）。**该资源不随仓库与 Docker 镜像分发**——jessibuca 是 GPL-3.0，随镜像分发会要求 PTPatronus 整体同样以 GPL-3.0 发布。

改为**后端按需自动获取**：

- 用户无需执行任何命令，docker compose 用户与源码用户体验一致
- 首次打开预览时后端自动下载 → 校验 sha256 → 落盘到 `DataDir/jessibuca/`（用户唯一会挂载持久化的目录，重启/换镜像不重下）
- 下载完成后本地直出，带 `Cache-Control: immutable`
- 下载中前端显示「正在准备播放器…」，完成后自动开始播放
- 无外网环境可预置：把三个文件放进 `DataDir/jessibuca/` 即可（校验和见 [assets.go](backend/internal/web/assets.go)），或跑 `bash scripts/fetch-jessibuca.sh`（供 CI/离线构建使用）

**离线/内网部署**：若运行环境不能访问 GitHub，把 `jessibuca.js` / `decoder.js` / `decoder.wasm` 预先拷入 `DataDir/jessibuca/`。后端每次读取都校验 sha256，文件缺失会自动补下。

未就绪时摄像头在线状态、掉线告警、历史快照等**全部正常**，仅实时预览不可用。

## 告警阈值

`MonitorTarget.Thresholds` 存 JSON，空字段回退默认：

```json
{"cpu_usage":90, "mem_usage":90, "disk_usage":90, "temp":75, "offline":true}
```

超阈值 +10 个点以内为 `warning`，更高为 `danger`；仅「未触发→触发」时新建告警并通知（去重），「触发→恢复」时静默 Resolve。

## 依赖（纯 Go，无 CGO）

- `github.com/shirou/gopsutil/v4` — 本机系统指标（v4 是当前主线）
- `github.com/bluenviron/gortsplib/v5` — RTSP 客户端（**v4 已弃用**，用 v5）
- `github.com/gosnmp/gosnmp` — NAS SNMP fallback
- 已复用：`golang.org/x/crypto/ssh`（远程采集）、`gorilla/websocket`（RTSP-WS 出口）

`go test ./internal/monitor/` 覆盖：`/proc` 解析、ONVIF 标签提取、阈值解析、Registry 分发、本机采集烟雾、告警状态转换去重、离线告警。RTSP 代理/真实设备采集因需硬件不在单测范围。
