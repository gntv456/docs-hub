## 0. 一句话结论

**过去一个月，旧报告的缺口正在以肉眼可见的速度关闭——12 项主要缺口已有 7 项落地，而且落地的质量不差（双端同构 + 带单测）。这让 v1 报告的"补作业清单"基本作废。**

但复评暴露了一个更值得警惕的新问题：**每一项都以"最小可行口径"闭环，没有一项做到"完整语义"。** 我们做出了 sidecar 字幕，但没有内封字幕和在线字幕下载；做出了跳过片头，但是纯手工标记，而 Jellyfin 的 Intro Skipper 是音频指纹自动全库扫描；做出了观影足迹，但藏在二级面板里而不是首页入口。

**因此 v2 的核心结论从"我们缺什么"变成"我们做了一半，另一半值不值得做"：**

| 判断 | 内容 |
|------|------|
| **三座山仍未动** | 实时转码 / 自适应码率、多用户家庭账户、TV 大屏端 |
| **其中一座的底座已经铺好** | ffmpeg 已进镜像与配置，Node 端已能 spawn 截帧 → 接一条 HTTP Range 转码流的成本比一个月前低得多 |
| **必须马上承认的好消息** | v1 提的 NFR「要么出画面，要么给一句可操作的中文提示」**已兑现**（`utils.js:259-275`、`setup-page.js:86`） |
| **新增的最大洞察** | 私有化场景下，部分竞品功能**不该照搬**（追剧日历/金币体系）——见 §6「别抄清单」 |
| **UI 的真问题不是不够炫** | 是「10 英尺 UI 缺失」+「浅色完善度低」+「玻璃拟态在低端 SoC 上的性能」——见 §5 |

## 2. 完成度审计：闭环 ≠ 追平

这一节是 v2 相对 v1 的方法升级。我们不再问"有没有"，而问"做到几分"。

### 2.1 字幕：从 0 到 60 分

已实现的确实扎实，值得肯定：

- SRT / ASS / SSA / VTT → WebVTT 转换，且 SRT 序号行的删除做了"后面必须紧跟时间轴"的前瞻断言（`subtitles.js:63`）——避免误删正文里恰好是数字的一行。这种边界意识是老手写出来的。
- GBK / UTF-8 嗅探 + BOM 剥离 + 解码失败回退宽松 UTF-8（`subtitles.js:46-54`）。中文 PT 用户的高频痛点处理到位。
- ASS 按 `[Events] Format` 动态取字段，未给 Format 时用默认序（`subtitles.js:19-21, 119-127`）。
- Blob URL 缓存带 LRU 淘汰（上限 8，`subtitles.js:179-183`），避免长视频反复转换。
- 儿童模式下明确"仅作辅助阅读，不提供外链下载"（`subtitles.js:290`）。

**但完整口径还差这些（对标飞牛影视 + Jellyfin）：**

| 能力 | 飞牛影视 | Jellyfin | 我们 | 缺口性质 |
|------|:--------:|:--------:|:----:|---------|
| 同目录 sidecar 字幕 | ✅ | ✅ | ✅ **已有** | — |
| MKV/MP4 **内封字幕轨**提取 | ✅ | ✅ | ❌ | **硬伤**：多数 PT / 蓝光原盘资源根本没有外挂文件，只有容器内封轨 |
| **在线字幕搜索下载** | ✅ 智能搜寻并自动下载 | ✅ OpenSubtitles 插件 | ❌ | 用户最省事的那一环缺失 |
| 多字幕轨切换 UI | ✅ | ✅ | ⚠️ 有选择面板，但依赖目录里有多个文件 | 内封缺失导致 UI 空转 |
| **字号 / 颜色 / 位置 / 描边** | ✅ 可调 | ✅ | ❌ 完全由浏览器 `<track>` 默认样式决定 | 家庭场景（老人 / 电视远距离）真实痛点 |
| **时间偏移校正** | ✅ 实时调整字幕延迟 | ✅ | ❌ | "字幕不同步"这一千古难题没法解 |
| ASS 特效保留 | ⚠️ 渲染器支持 | ❌ 同样降级 | ❌ `cleanAssText` 剥离 `{\...}`（`subtitles.js:99-105`） | 与 Jellyfin 同口径，可接受 |

> **验收口径建议（测试团队）**：补上**内封字幕提取**后，必须建立用例矩阵：MKV 内封 SRT / ASS、MP4 内封 tx3g、多轨（含 forced track / SDH）、带 BOM 的 GBK、UTF-16LE 编码、零长度字幕文件。

### 2.2 跳过片头片尾：从 0 到「手工作业」

这是我认为**最值得立刻修补的一处 UI 缺陷**，因为它不是能力问题，而是交互遗漏：

`openMarkerSheet`（`markers.js:157-161`）只暴露了三个按钮：

```
把 {now} 设为片头结束   → 写 introEnd
把 {now} 设为片尾开始   → 写 outroStart
清除片头片尾标记        → clear
```

**没有"设为片头开始"的入口。** 而写入时又把原有值回传（`markers.js:177`）：

```js
{ introStart: m.introStart, introEnd: Math.max(1, Math.round(now)), outroStart: m.outroStart }
```

`m.introStart` 从来只能保持初始的 `0`（`normalizeMarkers` 默认 0，`markers.js:30-32`）。也就是说：**我们假定所有片头都从 00:00 开始。**

- 对"一上来就是 OP"的剧集：OK。
- 对"前奏 20 秒正片 → 然后 OP"的日式番剧/部分国产剧：**永远标不准**，跳过按钮会在正片区间弹出。

对照 Jellyfin 的 Intro Skipper 插件：**后台扫描全库，用音频指纹自动检测 OP 区间，全剧集自动生效**，零用户操作。

| 维度 | 我们 | Jellyfin Intro Skipper |
|------|------|------------------------|
| 数据来源 | 用户手动拖到时间点再点按钮 | 后台任务，音频指纹比对 |
| 覆盖范围 | 逐条 / 逐剧集要有人先标记一次 | 全库自动，一次配置永久生效 |
| 冷启动体验 | 新入库的片子**永远没有**跳过按钮 | 入库后自动检测 |
| 我们的优势 | 零误判，零 CPU 开销，隐私无虞；剧集级共享（`markerKey`，`markers.js:24-27`）设计得很干净 | — |

> **建议**：短期先补一个"设为片头起点"按钮（半天工作量，解决逻辑残缺）；长期若要做自动检测，务必做成**可选开关 + 后台低优先级任务**，并明确告知需要 CPU 投入——自托管用户对"NAS 半夜偷偷满载"非常敏感。

### 2.3 观影足迹：做好了，但藏起来了

`footprint.js` 的实现质量很高——热力图重活全放后端，前端只铺稀疏天列表（`footprint.js:8-9`）；日期全用 `parseDayKey/dayKeyOf` 互逆函数处理本地日，并明确注释"不要用 `new Date(key)`，那是 UTC 解析，东八区会整体差一天"（`footprint.js:11-12, 17-27`）。**这是典型的踩过坑之后写出来的代码**，应该肯定。

但它是一个 `openFootprintSheet` 面板（`footprint.js:160`），需要主动点开。Immich 的 Memories 之所以能拉动回流，是因为它**主动出现在首页**，而不是藏在一个按钮后面。

| 项 | Immich Memories | 我们 |
|----|----------------|------|
| 入口层级 | 首页首屏卡片 | 二级面板 |
| 触发方式 | 系统主动推送 | 用户主动点击 |
| 文案钩子 | "N 年前的今天" | "那年今日" ✅ 已有 |

> **建议**：把"那年今日"做成首页 Feed 的一张**信息流插卡**（不是常驻横条），有往年内容时才出现。成本极低，因为数据和渲染函数都已经写好了。

## 3. 仍然横亘的三座山

### 3.1 转码：底座已经铺好，别再用"成本高"说服自己

这是本次复评最重要的**判断更新**。

v1 的结论是"全仓库无 ffmpeg 依赖，要从零引入"。一个月后：

| 已经具备 | 位置 |
|---------|------|
| 镜像内装了 ffmpeg | `Dockerfile:27`、`Dockerfile.go:26` |
| 配置项 `FFMPEG_PATH` | `backend/src/config.js:102-103`、`backend-go/internal/config/config.go:43,95` |
| Node 端已能 spawn ffmpeg 并做了**并发去重 + 失败墓碑 24h** | `backend/src/services/thumbnail.js:6-7, 20, 121` |
| Go 端封面兜底链路已接 ffmpeg | `backend-go/internal/route/media.go:414` |
| 缺失时的静默降级到占位图 | `thumbnail.js:7`、`thumbnail-degrade.test.mjs` |

**结论：难点"能不能调起 ffmpeg"已经解决。** 剩下的是把它接到 HTTP Range 响应上，且我们可以在**已失败的基础上才降级**——用户已经在 `utils.js:273` 被提示"格式不支持"了，此时再补一句"正在转码重试"的成本远低于从零引 ffmpeg。

**外部现实更需要催促这件事：**

| 竞品 | 2026 现状 | 强度 |
|------|---------|:----:|
| 飞牛影视 | 2026-08-20 官方更新：**新增视频自动转码播放，可根据当前网络和视频情况自动选择合适分辨率，加快启播**；播放器支持 TV 端 RKMPP/Vulkan/V4L2 M2M 编解码 | 【中】官方更新日志 |
| Jellyfin | 2026-09 稳定版 **12.1**（12.0 于 9/8 发布）；硬件转码全免费，捆绑 FFmpeg 7.1；Intro Skipper 音频指纹自动检测 | 【中】多源交叉 |
| Plex | 硬件转码需 Plex Pass；$249.99 终身 / 远程播放已转付费 | 【弱】单一评测站，仅作背景 |
| 红果短剧 | 弱网自适应码率；多清晰度自适应 360P/480P/720P/1080P，可手动锁定 | 【弱】下载站文案 |

**最小闭环（可单独立项，30 天内可交付）：**
1. 播放失败（`MediaError` 3/4）→ 服务端按需起 ffmpeg 转封装/转码 → 输出 MP4(H.264+AAC) 走 Range；
2. 优先做**remux（`-c copy` 换容器）**，编解码不变，CPU 开销极低，能解决大量"MKV/ASS 在 Safari 打不开"的场景；
3. 只有 remux 仍失败才降级真转码；
4. 前端提示从"换个浏览器"升级为"正在为你转换格式（首次约需 X 秒）"。

> **NFR 断言（测试团队口径）**：编码矩阵（HEVC 10bit / HDR / VC-1 / AV1 / ASS 特效 / 5.1 音轨 / 内封字幕）× 客户端矩阵（Chrome / Safari / Edge / 安卓 WebView / iOS Safari / 电视浏览器）× 网络档位（LAN / 4G / 高延迟），**任意组合下要么出画面，要么给一句可操作的中文提示，绝不允许静默转圈**。这条 v1 只在错误提示上兑现了，播放路径尚未兑现。

### 3.2 多用户家庭账户：README 第一目标用户与现实的最大落差

README 第一行目标用户是"NAS · 网盘 · PT 资源"的家庭用户，但 `auth.go:97` 写死 `role = "admin"`，注释坦承"单机/家庭部署：登录即管理员"。

现实是：我们已经做了高质量的儿童模式（fail-closed 实现，见 v1 §2.3），但它建立在"**整屋共用一个账号**"的前提下——孩子的橙 timeline 和父母的观影历史混在同一份数据里。而"继续观看""那年今日""推荐排序"这三项刚刚做好、最能拉动回流的功能，**恰恰是账号共享场景下最先崩坏的**：妈妈首页刷到孩子的动画推荐，孩子在续看横条里看到父母在追的剧。

> 这不是 bug，但会让 §2 我们刚做完的所有个性化投入的收益打折。

参照物（【中】多源交叉）：飞牛影视提供**多用户档案**，每人独立观看历史 / 收藏 / 推荐，父母一句话的用法；Jellyfin 提供免费多用户 + 按库授权 + 家长控制。

**越权测试是这条线的验收核心**：A 用户凭 ticket 能否取到 B 用户私有目录下的媒体；儿童身份能否反向切回家长；Ticket 时效与一次性语义在引入用户维度后是否会退化。

### 3.3 TV 大屏端：家庭场景的主屏幕

全仓零命中 `Android TV|遥控器|焦点管理|dpad|10英尺`。Web / Electron / Android / 鸿蒙 / iOS 五端规划里，唯独缺了家庭场景实际使用频率最高的那块屏。

v1 的建议依然成立且性价比最高：**先做 TV 浏览器适配（焦点管理 + 10 英尺 UI + 格子尺寸），不做原生 APK**。参照 iOS 27 液态玻璃的设计语汇，我们在遥控焦点态上的视觉表现有先天优势。

验收口径：遥控器上下左右 + 返回 **100% 完成所有核心旅程**，全程不可假设鼠标可用。

## 5. UI 界面专项

用户特别点名 UI，这里单独展开。先说结论：**我们的 UI 不是"不好看"，而是"在错误的设备上很好看"。**

### 5.1 主题系统

实测 7 套主题（`backend-go/internal/service/themes.go:21-92`）：

| # | ID | 名称 | 模式 | 主色 |
|:-:|----|------|:----:|------|
| 1 | `tanqu-aurora` | 探光极光 | dark | `#7C5CFF` 紫 + `#FF7AB8` 粉 |
| 2 | `ios27-night` | 夜航玻璃 | dark | `#0a84ff` 蓝 |
| 3 | `ios27-dawn` | 晨雾浅色 | **light** | `#007aff` 蓝 |
| 4 | `douyin-ink` | 墨韵沉浸 | dark | `#fe2c55` 抖音红 |
| 5 | `forest-jade` | 青瓷松风 | dark | `#2acfaa` 青 |
| 6 | `amber-cinema` | 琥珀影院 | dark | `#ff9f0a` 琥珀 |
| 7 | `lavender-soft` | 紫雾柔光 | **light** | `#7c5cff` 紫 |

- **数量上处于主要竞品之上**（Jellyfin / Plex / 飞牛均为 1–2 套深浅切换）。这是明确优势，应保留并对外主张。
- **但明暗比 5:2，浅色只占 29%。** 且 7 套里有 4 套是深色沉浸向（极光 / 夜航 / 墨韵 / 琥珀影院），取向高度重合；浅色只有两条，且都是偏冷的蓝与紫。**建议下一轮优先补 1–2 套暖色浅主题，而不是再堆第 8 套深色。**
- `UI规范.md:31` 对浅色的描述只有一行"浅色模式反转玻璃为深色 8% 透明 + 白底渐变"。**7 套主题共享一份规范碎片，规范已经落后于实现**，建议把 themes.go 反向同步回 UI 规范，并针对浅色建立独立的对比度/层级标准。

### 5.2 三个需要实测而非臆断的 UI 风险

| 风险 | 说明 | 建议验证方式 |
|------|------|-------------|
| **毛玻璃在低端设备的成本** | `UI规范.md:7` 规定 `backdrop-filter: blur(28px) saturate(180%)`。这在 N100 / 老旧安卓盒子 / ARM NAS SoC 上是明确的 GPU 负担，而我们恰恰目标国产 NAS 用户 | 在目标机型上实测 FPS 与耗电；低端设备应自动降级为半透明纯色 |
| **7 套主题 × 深浅的对比度** | 已有 `aria-label` / `prefers-reduced-motion` 规范，但未见对比度回归 | 7 套主题 × 关键页面（Feed / 发现 / 片库 / 详情 / 弹层）跑 AA 检查，**尤其留意浅色主题下弹幕白底可读性** |
| **首页入口堆叠** | 竖滑 Feed + 发现页双列已是高密度；本轮又加入续看横条、观影足迹热力图，首页 enter point 从 1 条变成 4 条 | 走查首页是否需要分区节奏，避免"横条堆叠症"；推荐/priority 排序要明确 |

### 5.3 UI 上明确值得夸的部分

- **`#cw-slot` 挂在 `#feed` 之外**（`continueWatching.js:12-14`, `index.js:54`），并写下这段注释解释"插入任何流内元素都会让位置数学整体错位"——窗口化 UI 的经典坑，提前在注释里锁死了后续维护者的手。这是可贵的工程自觉。
- **`onboardingHtml` 区分儿童话术**（`templates.js:24-31`）：孩子看到的是"家长还没有为你添加内容哦"，而不是冷冰冰的"没有内容"。
- **失败原因可见化**（`setup-page.js:86` 注释："只显示『重试』等于让用户猜——把 MediaError 翻成可行动的中文"）。
- **纯函数与副作用分离**：`subtitles` / `markers` / `footprint` / `continueWatching` / `feedback` 五个模块都把可测逻辑抽成导出纯函数，并配了单测。这种一致性说明不是某一个人的偶然发挥，而是团队约束在起作用。

## 6. 别抄清单：私有库场景下不该照搬的竞品功能

这是 v2 相比 v1 的方法补强。**对标的意义不在于把表格全打勾。**

| 竞品功能 | 为什么不适合我们 | 若要借鉴，该怎么改造 |
|---------|-----------------|---------------------|
| **追剧日历 / 更新提醒 / 预约** | 红果的价值建立在"平台持续上新"之上。**私有库的剧集是静态导入的，不存在"下周三更新第 8 集"**，做一个永远空着的日历是负资产 | 改造成 **"还剩 N 集没看 / 上次看到第 X 集 / 已看完 30/40"** 的进度语义，挂到剧集详情与续看横条。这才是私有库的真实追剧心智 |
| **金币 / 签到 / 提现体系** | 依赖平台补贴与 DAU 变现，自托管产品无任何承接面 | 完全不要做 |
| **虚拟放映厅（好友连麦同步观影）** | 依赖中心化房间服务与陌生人社交池 | 低优先级。家庭场景可退化成 **"局域网内多设备同步进度"**（这个是有价值的，且不依赖外网） |
| **社交裂变驱动的增长机制**（邀请红包 / 分享返利 / 看剧赚金币） | 自托管单机 / 家庭部署既无变现通路，也无陌生人社交池；照搬只会做出一堆永远点不动的空入口 | 完全不要做 |
| **完整 ABR（多码率切片 HLS/DASH）** | 这是流媒体公司的工程重心，成本极高 | 先做 §3.1 的"失败后降级转码"，再看数据决定是否要 ABR。不要为了完整性跳过闭环 |

> 保留这份清单的意义：**它可以阻止我们把工程预算花在"看起来与竞品对齐了，但对用户没有意义"的功能上。**

## 7. 我们应当继续主张的优势

（承接 v1 §4，并根据本次复评补强）

1. **多源聚合**：NAS 挂载 + WebDAV（群晖/坚果云/Alist）+ PT/寸光集。Jellyfin/Plex/Emby 都不原生做网盘聚合，这是国产用户的高频真实组合。【强】
2. **双后端同构 + 纯函数单测密度**：本轮新增的 `collections` / `feedback` / `playback_markers` / `stats` / `subtitles` 五项，每一项都在 Node 与 Go 两端逐字段对齐，且都配了 `_test.go`。这不是巧合，是可复制的工程范式，建议写进对外技术博客。
3. **儿童模式 fail-closed + 纵深防御**：`canPlayInKidsMode()` 查询失败一律拦截；启动锁以服务端 profile 为唯一真相；区分 401 与网络抖动；负反馈在儿童模式关闭（`feedback.js:13-14`）。源码级严谨度高于同价位竞品。
4. **播放失败的可解释性**（本轮新增）：已兑现 NFR。多数自托管产品在这一层是无声黑屏。
5. **成本与分发**：Docker Compose 多平台模板覆盖飞牛 / 威联通 / 群晖 / 极空间 / 绿联，这是国产 NAS 才懂的分发路径。
6. **隐私叙事**：2026 年 Plex 远程播放转付费、Jellyfin 仍需自建反代，"数据留在你的 NAS"是可销售的故事。
