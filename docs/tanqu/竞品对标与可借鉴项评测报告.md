## 0. 一句话结论

**我们的产品叙事（"自己的片库 + 抖音交互 + 影视元数据"）是站得住的，且已经把"交互层"做到了竞品平均线以上；真正被拉开差距的，不是 UI，而是「播放兼容层」和「家庭多用户 / 大屏生态」这两块基础设施，以及一个常常被自托管产品忽视的东西：让库随时间"变活"的能力（续看、年度回忆、观影热力图）。**

按收益排序，最值得立刻借鉴的 5 条：

| 序 | 借鉴来源 | 借鉴点 | 我们的现状 | 预估收益 |
|:--:|---------|--------|-----------|---------|
| 1 | Jellyfin / 飞牛影视 / Plex | **播放兼容层：转码 + 硬件解码 + 字幕** | 仅 `http.ServeContent` 直传（Range 支持 OK），全仓库无 ffmpeg/ffprobe 依赖，无字幕概念（`frontend` 零字幕相关代码） | 决定"外网 / 移动网 / 电视端能不能播"，是**可用性红线**而非加分项 |
| 2 | Immich + 飞牛影视 | **让库"活"起来：那年今日、观影热力图、年度报告** | 有 `/api/history` 与"我的—看过"，但只是列表，无数据可视化、无固定入口回放钩子 | 日均会话时长、回流率（对标 Immich Memories 的"情感钩子"） |
| 3 | Jellyfin / Plex / 飞牛 | **真正的多用户家庭账户 + 邀请 + 分级权限** | 只有"家长 / 儿童"身份切换（`/api/profile/*`），无独立成员账户与邀请体系 | 直接命中 README 第一目标用户「家庭 NAS 用户」 |
| 4 | Jellyfin + 飞牛 + 红果 | **TV / 大屏端（至少 Android TV）** | 五端规划里 Web / Electron / Android / 鸿蒙 / iOS，**缺 TV 端**；家庭场景的主屏幕是电视 | 家庭场景的主入口缺失，等于把客厅让给竞品 |
| 5 | Immich 上手流程 | **首次部署向导 + 样本自检（可自证的 onboarding）** | 需 compose → 挂卷 → 加源 → 触发扫描 → 手动刮削；`TANQU_AUTH_DISABLED=1` 演示开关存在 | 决定 30 天留存，"首次扫描到可播视频成功率" 才有意义 |

## 1. 评测方法与竞品样本

### 1.1 为什么选这四类，而不是只比 Jellyfin

好学探索同时踩在三条赛道上，必须**分层对标**，否则会得出"我们样样不如 Jellyfin"这种无用的结论：

| 层 | 竞品 | 我们向它学什么 |
|----|------|----------------|
| A. 私有化媒体服务器 | **Jellyfin**（开源、全功能免费）、**Plex**（客户端打磨）、**Emby**（中间态）、**飞牛 fnOS 影视**（国产、刮削 + 硬件转码 + 多端同步） | 元数据 / 播放兼容 / 多用户 / 家庭场景 / 国产 NAS 用户的真实预期 |
| B. 公域 Feed | **抖音**、**小红书** | 竖滑沉浸、内容负反馈、双列瀑布的信息密度 |
| C. 短剧剧场 | **红果短剧**、河马剧场 | 追剧链路：选集、更新提示、追剧日历、倍速、离线缓存、榜单 |
| D. 自托管体验标杆 | **Immich** | 如何让自托管产品"不像折腾玩具"：上手、手机 App、Memories、外部库、软删除 |

### 1.2 判定规则

- ✅ 已在代码中确认存在（有实现文件 / 路由 / 分支）
- ⚠️ 部分存在或仅覆盖部分场景
- ❌ 未发现任何实现痕迹

## 3. 可借鉴优点清单（P0 / P1 / P2）

### P0 — 应尽快立项

**P0-1　播放兼容层：转码 + 硬解 + 字幕**
- 学谁：Jellyfin（全功能免费，HDR→SDR 免费，这在 2026 年是很强的卖点）、飞牛影视（GPU 硬解 + 音频源码输出）
- 现状：`backend-go` 无 ffmpeg；`frontend/src` 无任何字幕相关实现；`docs/策划文档.md` §11 把它列为"开放问题"——这个决策现在已经可以回答了：竞品全是"有"，用户预期已经形成。
- 建议最小闭环：**至少做"失败的直播放 → 自动降级转码 + 外挂字幕 sidecar 自动识别（同目录同名 .srt/.ass）"**，不必一步到位做 ABR 多码率。
- 验收（测试口径）：编解码矩阵测试表 × 客户端矩阵（Chrome/Safari/Edge/安卓 WebView/iOS Safari/电视浏览器）× 网络档位（LAN / 4G / 高延迟）。**新增 NFR 断言：任意组合下要么出画面，要么给出一句可操作的中文提示，不允许静默转圈。**

**P0-2　多用户家庭账户体系**
- 学谁：Jellyfin（多用户 + 家长控制免费）、飞牛（多用户档案各自历史/收藏/推荐）、Immich（Partner Sharing）
- 建议：保留现有"家长/儿童"作为**账户内的快速切换**，在其上新增账户层。邀请用一次性的、带权限作用域的邀请码。
- 验收：**必须包含越权测试**——A 用户凭 ticket 能否取到 B 用户的私有目录下的媒体；儿童身份能否反向切换回家长。现有 ticket 鉴权要重跑穿透用例。

**P0-3　TV / 大屏端（至少 Android TV）**
- 学谁：Jellyfin 官方 Android TV 客户端；红果的电视版
- 理由：家庭用户的主屏幕不在手机。当前五端规划把这一屏漏了。
- 建议：**先做 TV 版浏览器适配（遥控器焦点管理、10 英尺 UI、格子尺寸），比做原生 APK 便宜得多**，可作为 P0-3 的第一步。
- 验收：遥控器上下左右/返回 100% 可完成所有核心旅程；无鼠标可用性。

### P1 — 明确能带来留存的体验项

**P1-1　让库"活"起来（Immich Memories + 飞牛观影记录）**
- 借鉴：**那年今日卡片**（Immich 证明这是自托管产品唯一的"非功利性回流"钩子）、**观影热力图（年/季/月/周）**、**年度观影报告 + 超越 X% 用户式成就**（红果已在做）。
- 现状：`/api/history` 有数据，但没有入口把数据变成回访理由。
- 验收：数据正确性（跨时区"今天"的定义、"看过"去重）、空数据态、以及**性能——热力图不要在大库上触发全表扫描**。

**P1-2　负反馈与推荐可调**
- 学谁：抖音 / 小红书"不感兴趣 / 减少此类"。
- 现实价值：我们的 AI 推荐是"可解释本地混合排序"——这是优势，但**没有纠偏通道**。用户遇到不相关内容只能忍着，这是私有库最常被吐槽的地方（"我给孩子/老人看，却总刷到 XX"）。
- 建议：长按/更多里加"不感兴趣"，并在设置里暴露一个"为什么推荐这条"的解释面板（把现有可解释性变成 UI）。
- 验收：负反馈即时生效 + 持久化 + 跨会话不回弹。

**P1-3　追剧三件套（红果）**：剧集详情页补"更新至 N 集"、追剧预约、追剧日历 / 更新提醒。当前 `episodes.js` 有选集 sheet，缺更新与提醒语义。

**P1-4　命名收藏夹 / 播放列表**：二元收藏 → 可命名、可排序、可分享的收藏夹。小成本高感知（参考红果"可创建多个分类收藏"、Jellyfin 合集）。

**P1-5　Continue Watching 横条（Jellyfin Next Up）**：把"我的—看过"提升为首页入口，横版卡片 + 进度条 + 一键续播，覆盖非剧集内容。

**P1-6　可自证的 Onboarding（Immich）**：照搬 Immich 的"15–30 分钟 → 出画面"路径设计：注册管理员 → 引导添加媒体源 → **立即跑一次小样本扫描并播放一段，作为"成了"的证据** → 再提示全量扫描与刮削。同时给 `TANQU_AUTH_DISABLED` 一个**更醒目的生产环境告警条**。

### P2 — 打磨与护城河

- **P2-1 语义搜索 / 以图搜图**（Immich CLIP、飞牛以文搜图）——结合已有 AI 文件名解析，做成"AI 辅助找片"，这是比 syntactic search 更上位的卖点。
- **P2-2 跳过片头 OP/ED**（Jellyfin 免费 / Plex 需 Pass）——我们免费提供即胜点。
- **P2-3 离线缓存**（红果批量 + 断点续传）——移动端通勤场景。
- **P2-4 插件化刮削源**（已在 v1.0 路线图）——学 Jellyfin 的插件生态（字幕源、AniDB、IPTV、LDAP）。
- **P2-5 Trash 软删除**（Immich 明确采用）——当前删除即移除，家庭共享场景不可逆是真实痛点。
- **P2-6 备份/导出/迁移**（Immich 提供了可观的一键 pg_dump 流程，同时坦承"不要作为唯一备份"，这点诚实很重要）——我们需要：元数据导出 + 恢复演练；**并且应当像 Immich 一样在文档里明确"本项目不是你的第二份备份"**。
- **P2-7 弹幕做成**真正的差异化杀手皮革馆——飞牛客户端"MPV 弹幕自动匹配"，我们可以更进一步：评论弹幕已有的基础上，加"同剧集观众在第 N 集留下的评论"时间轴弹幕。

## 4. 我们应当保留并对外主张的优势（不要因为对标而自废武功）

1. **多源聚合**：NAS 挂载 + WebDAV（群晖/坚果云/Alist）+ PT/寸光集。Jellyfin/Plex/Emby 都不原生做网盘聚合；这是国产用户的高频真实组合。
2. **私有化 + 零 account 依赖主张**：2026 年 Plex 把远程播放纳入付费、终身 Pass 涨到高位、且两年两度数据事故——**"数据留在你的 NAS"现在是可销售的故事**，不是默认属性。
3. **可解释的本地 AI 推荐**：相比竞品的黑盒"千人千面"，这在"给全家共用一台设备"的场景里是可贵的。
4. **儿童模式的 fail-closed 实现**：源码级的严谨度高于同价位竞品，建议写成一篇技术博客对外发布。
5. **成本优势**：Jellyfin 免费但需大量配置；我们的 Docker Compose 多平台模板（飞牛/威联通/群晖/极空间/绿联）已经覆盖了国产 NAS 主流机型，这是国内竞品才懂的分发路径。

## 5. 测试团队追加：现有保障 vs 应有保障

### 5.1 现有做的不错的地方（值得肯定）

- `npm run e2e`（API 层）+ `npm run e2e:browser`（puppeteer-core，25 项功能矩阵）双套件，且**自动捕获页面错误 / 5xx / API 调用统计**——这套设计思路是对的。
- Go 侧 CI 门禁：`go vet` + 函数长度 ≤80 行 + 编译 + 单测（auth/db/http/scraper）+ 真实启动后的 `/api/health` 校验。函数行数门禁在允许 `//nolint:funclen` 白名单的同时要求谨慎使用，尺度合理。
- 锁屏/身份相关的 edge case 考虑得很仔细（区分 401 与网络失败、fail-closed、`overlay.js` 中 `unclosable` 语义），属于"看过事故才写得出来"的代码。

### 5.2 建议增补的测试维度（按优先级）

| 缺口 | 为什么重要 | 具体建议 |
|------|-----------|---------|
| **性能基线与回归** | NFR 已写"1 万文件增量扫描 < 2min""1080p 起播 < 1.5s"，但未见自动化守护 | 把这两条做成 CI 之外的**每晚固定样本基准**，输出趋势，超标即失败；刮削批量任务要有吞吐基准 |
| **编码/客户端兼容矩阵** | P0-1 的前置能力 | 建立一个 20–30 个样本文件的"坑服 lie 样本库"（HEVC 10bit、HDR、ASS 特效、5.1 音轨、mkv 内封字幕、异常 container），每次发布跑全矩阵 |
| **双后端一致性（Node vs Go）** | 这是本仓库独有的结构风险 | 同一套契约测试同时打两个后端，比对状态码、错误码、字段、鉴权行为；**尤其是 ticket 鉴权与路径穿越防护两处安全语义** |
| **安全测试形式化** | 私有化产品的卖点是隐私 | 路径穿越（`isPathAllowed`）、WebDAV 凭据存储与日志脱敏、ticket 时效与一次性、限流误伤、以及"演示模式开关被误留在生产"的发布前断言 |
| **可访问性与多主题可读性** | 已有 `aria-label`、`prefers-reduced-motion` 规范，但未见验证 | 7 套主题 × 深浅色 × 关键页面，跑对比度 AA 检查；毛玻璃 `backdrop-filter: blur(28px)` 在低端安卓 WebView / 老旧 NAS SoC 上的 FPS 与耗电需实测 |
| **浅色模式完整度** | 7 套主题中仅 2 套为 light，且 UI 规范对浅色只有一行描述 | 浅色模式专项走查，尤其海报墙/detail 页/弹层/以及"弹幕白底可读性" |
| **家庭并发与父子锁真实性** | README 目标并发 5–20 用户 | 写个并发测试：20 会话同时播放 + 家长改分级的实时生效性 + 定时锁跨设备同步（儿童删 localStorage 能否绕过——代码注释显示已修，需要有回归用例守住） |
| **破坏性恢复演练** | Immich 用户最真实的痛点是"升级后 db 迁移失败" | 元数据导出 → 全新实例导入 → 播放/历史/收藏一致性校验，纳入发布 checklist |

## 6. 90 天建议节奏

| 阶段 | 目标 | 关键交付 |
|------|------|---------|
| 第 0–30 天 | 补齐"能不能播"这条下限 | P0-1 最小闭环（直播失败降级转码 + sidecar 字幕）；建立编码兼容样本库与矩阵测试 |
