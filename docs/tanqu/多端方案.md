# 好学探索 · 多端客户端方案

> 覆盖：**Web 端 · 电脑端 · 手机端（Android）· 鸿蒙端 · iOS 端**  
> 原则：**一套业务 UI + 统一 Docker 后端 + 各端薄壳原生能力**

---


| 端 | 技术壳 | 分发形态 | 优先级 |
|----|--------|----------|--------|
| Web | 浏览器直连 Docker 静态资源 + PWA | URL / 内网域名 | P0 |

| 鸿蒙端 | HarmonyOS NEXT ArkWeb 容器 + 原生桥 | 应用市场 / 调试包 | P1 |

> 登录方式全端统一：好学 PT / 寸光集，参考 `D:\jiapu`；壳内可配置后端地址。

## 2. 共享层（一次开发，五端复用）

### 2.1 共享前端 `frontend/`
- 竖滑 Feed、发现、片库、随手拍 UI、登录、设置
- iOS 27 Liquid Glass 视觉
- 鉴权模块（session / apiBase，对齐 jiapu 的 `js/auth/session.js`）
- 能力探测：`Capacitor` / `Electron` / `HarmonyBridge` / 纯 Web

### 2.2 共享协议
- REST API 见 `docs/API设计.md`
- 会话：Cookie + Bearer Token 双通道（壳环境优先 Bearer）
- 媒体：`/api/media/:id/stream` Range 播放

### 2.3 原生能力抽象 `platform/`

```ts
interface PlatformBridge {
  getName(): 'web' | 'desktop' | 'android' | 'ios' | 'harmony'
  pickMedia?(): Promise<File>          // 相册
  openCamera?(opts): Promise<File>     // 随手拍
  setSecureStorage?(k,v): Promise<void>
  getSecureStorage?(k): Promise<string>
  openExternal?(url): Promise<void>
  getDeviceInfo?(): Promise<DeviceInfo>
}
```

各端实现同一接口，业务代码不写 `if (android)` 散落逻辑。

## 3. Web 端（P0）

### 形态
- Docker `api` 同时托管前端静态资源
- 支持安装为 **PWA**（manifest + service worker）
- 桌面浏览器与手机浏览器均可用

### 能力
| 能力 | 方案 |
|------|------|
| 播放 | HTML5 video + Range |
| 随手拍 | `getUserMedia` / 文件选择降级 |
| 登录 | 标准 Cookie 同站；跨域时 Bearer |
| 离线 | SW 缓存壳页面；视频不强制离线缓存 |

### 发布
```bash
docker compose up -d
# 打开 http://<host>:8787
```

## 4. 电脑端（P0）— Windows / macOS / Linux

### 技术选型
- **Electron**（与 `D:\jiapu\electron` 同类，生态成熟、打包熟）
- 备选后续可迁 Tauri（包体更小），MVP 先 Electron 求稳

### 目录
```
desktop/
  electron/
    main.js          # 窗口、托盘、协议
    preload.js       # 安全桥
  package.json
```

### 能力
| 能力 | 方案 |
|------|------|
| 窗口 | 圆角沉浸、深色标题栏，贴合 iOS27 气质 |
| 后端地址 | 首次启动引导填写 / 记住上次 |
| 本地快捷键 | 空格播放、方向键切集 |
| 下载/导出 | 可选把收藏元数据导出 |
| 自动更新 | generic provider / GitHub releases（v0.2） |
| 深链 | `tanqu://media/<id>` |

### 打包产物
- Windows：`好学探索-Setup.exe` + 便携 zip
- macOS：`dmg`（需签名公证才顺滑）
- Linux：`AppImage` / `deb`

### 用户路径
1. 安装电脑端  
2. 填入家庭 Docker 地址（如 `http://192.168.1.8:8787`）  
3. 好学/寸光集账号登录  
4. 全屏刷 NAS 片库

## 7. 鸿蒙端 HarmonyOS NEXT（P1）

### 推荐路线（务实）

**阶段 A（快）— ArkWeb 容器壳**
- 用 HarmonyOS 原生工程创建全屏 `Web` 组件加载：
  - 内网 Docker 前端地址，或
  - 打包进应用的本地 H5 资源 + 远程 API
- 通过 `JavaScriptProxy` / 双向桥暴露：
  - 相机、文件选择、安全存储、返回手势

**阶段 B（体验增强）— 关键页面原生化**
- 登录页 / 播放器 / 随手拍 用 ArkTS 重做
- Feed 列表仍可 Web 或半原生

**不建议 MVP 重写整套 ArkUI 业务**（成本高、与其它端分叉）。

### 目录
```
harmony/
  entry/src/main/ets/
    pages/Index.ets          # ArkWeb 容器
    bridge/TanquBridge.ets   # 原生桥
  AppScope/
```

### 分发
- 华为应用市场（需开发者认证）
- 内部调试 hdc 安装

### 兼容说明
- HarmonyOS NEXT 与安卓 APK 不互通；必须独立包
- 若需兼顾旧鸿蒙/安卓双框架，Android 包仍走 Capacitor

## 9. 工程与仓库结构（多端）

```
HX-Tanqu/
├── backend/                 # Docker API（唯一业务后端）
├── frontend/                # 共享 Web UI
├── desktop/                 # Electron 电脑端
├── mobile/                  # Capacitor 配置
│   ├── android/
│   └── ios/
├── harmony/                 # 鸿蒙 ArkWeb 壳
├── docs/
├── docker-compose.yml
└── scripts/
    ├── build-web.mjs
    ├── build-desktop.mjs
    ├── build-android.mjs
    └── build-harmony.md
```

### 构建流水线（建议）
1. `frontend` build → `dist`
2. Web：拷贝进后端静态目录 / nginx
3. Desktop：Electron 打 `dist`
4. Android/iOS：`cap sync` + 原生构建
5. Harmony：HVigor/DevEco 构建，加载同一 `dist` 或在线地址

## 10. UX 一致性策略

1. **同一视觉语言**：iOS27 液态玻璃在五端不换皮  
2. **同一信息架构**：Tab = 首页 / 发现 / 拍 / 片库 / 我的  
3. **自适应**  
   - 手机/鸿蒙/iOS：竖屏沉浸  
   - 电脑/宽屏 Web：可左栏片库 + 右 Feed，或居中手机框模式  
4. **首次引导**：未配置服务器 → 统一「连接家庭服务器」向导

## 12. 风险与应对

| 风险 | 应对 |
|------|------|
| iOS 编码不兼容 | 上传/库内偏好 mp4+h264；后续 ffmpeg worker |
| 鸿蒙审核与 Web 壳限制 | 关键页原生化；避免纯空壳无价值 |
| 家庭 HTTPS 证书 | 内网 HTTP + 明文风险提示；可选反代证书 |
| 多端 token 丢失 | 安全存储抽象 + 登录态恢复 |
| 包体与发版成本 | 共享前端，壳仓库 submodule/ monorepo |

---

## 13. 决策结论（产品拍板）

1. **后端只维护一套 Docker 服务**  
2. **UI 只维护一套 frontend**  
3. **五端都是壳 + 桥，不五次重写业务**  
4. 落地顺序：**Web → 电脑 → Android → 鸿蒙 → iOS**  
5. 登录与 jiapu 对齐，降低账号体系成本  

此方案满足：Web 端、电脑端、手机端、鸿蒙端、iOS 端全覆盖，同时控制研发分叉风险。
