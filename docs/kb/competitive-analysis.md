## 0. 结论摘要（先说重点）

1. **市场出现明确的窗口期，且窗口就在现在。** WakeUp 课程表 2025-09 起商业化（6.0.30 塞入搜题、包体 5MB→30MB，12 月起开屏广告），App Store 中国区近期评分跌到 **1.8/5**，小红书/知乎集中出现「去广告教程」「出走记录」。用户对课表 App 的两大敏感点是 **开屏广告** 与 **行踪数据隐私**。我们「本地优先、无广告、不注册」的定位正好打在痛点上，但目前这条卖点在产品里几乎不外显（只在设置里一句"本地优先，不上传课表"），**这是最低成本、最高杠杆的 P0**。

2. **能力对照上，我们"中盘不弱、两翼缺失"。** 中盘（课表渲染、单双周、冲突检测、片段级自定义时间、通知、导入导出、响应式）已达甚至优于多数竞品；**两翼——「系统级触达」（Android/iOS 桌面小组件、锁屏、实时活动）与「录入自动化」（教务一键导入、分享码/口令、竞品文件迁移）是硬缺口**，而这两翼恰恰是用户选择课表 App 的第一决策因子（不打开 App 就能看到下一节课；10 秒建好表）。

3. **有一批"已在设置里写了名字但没实现"的占位项，属于测试意义上的高危体验缺陷。** 全局设置页里的「将课表添加到桌面」「日期之间调课」「自定义空课图片」「清除内置浏览器缓存」目前都只有说明文案、无功能。用户看到入口点进去发现不能用，比没有这个入口更伤信任——建议要么实现、要么从 UI 移除并改为"规划中"。

## 2. 差距清单（GAP）与建议

级别说明：**P0** = 上线/增长硬门槛；**P1** = 首轮迭代补；**P2** = 规划。每条都给出测试可验收的标准。

| ID | 级别 | 差距 | 竞品做法（证据） | 建议 | 验收标准（可测） |
|---|---|---|---|---|---|
| G-01 | **P0** | Android / iOS 桌面小组件完全没有 | 超级课程表 4×4；WakeUp 4 种尺寸并可选课表；鸿蒙日历十几种配色 | 补 AppWidget + WidgetKit，至少 3 尺寸（今日/本周/下节课） | ① 冷启后 5s 内首刷；② 跨天/跨节自动刷新；③ 点击深链进课程页（复用鸿蒙深链白名单策略）；④ 省电限制下有降级提示；⑤ 深色模式与主题色跟随 |
| G-02 | **P0** | 「无广告 / 不注册 / 本地优先」不外显 | WakeUp 因广告评分跌至 1.8/5 | 首启引导第三屏、关于页、商店文案统一强调；新增"隐私承诺"卡 | 文案一致性走查 3 端；引导完成率埋点 |
| G-03 | **P0** | 竞品迁移入口埋太深 | 无竞品提供"从 WakeUp 导入" | 把 `CompetitorScheduleParser` 提升为一级入口「从其他课表 App 导入」，支持选文件/粘贴 JSON，自动识别来源 | 4 种格式样本各 1 份导入成功率 100%；识别不出时明确提示并回落文本识别；脏数据被钳制而非入库 |
| G-04 | **P0** | 教务系统导入仍为 Noop | WakeUp 2000+ 高校 10 秒导入 | 短期：保留入口但明确"内测中/可申请适配"并收集学校名；中期：接 3~5 所试点 | 未适配学校有明确文案而非转圈；已有 https 强制（SEC-4）继续守住 |

## 3. UI / 交互层可直接借鉴的细节

1. **当前时间红线 + 已结束课程降透明度**（G-07）：课表类 App 的"通用语言"，用户一眼知道现在在哪、还剩多久。成本极低，感知极高。
2. **今日视图 / 日视图**（G-06）：周视图适合"规划"，日视图适合"当下"。竞品把它放进小组件和首页切换，我们只有周视图 + 月历。
3. **拖拽的"吸附高亮 + 撤销"**（G-09）：我们已有 `LongPressDraggable`，但缺少落点格高亮反馈与撤销；建议拖动时目标格描边高亮 + 松手后 SnackBar 撤销。
4. **课表块三档信息密度**（G-13）：小屏放不下"课名+教师+地点"时，用户自己选放什么，比我们写死更省心。
5. **字体大小应用内档位 + 多行备注**（G-11/G-12）：直接命中 WakeUp 改版的公开差评点（"字体不是太大就是太小""备注只能显示一行"），是低成本的口碑承接点。
6. **预设皮肤一键套用**（G-12）：把"主题色+玻璃强度+格子高度+圆角+背景"打包成 3~5 套预设（清新/暗夜/纸感/霓虹/玻璃极简），比散落 5 个滑杆更容易出效果，也更适合截图传播。
7. **小组件与锁屏的统一配色**（G-01/G-16）：课表 App 的截图传播基本发生在桌面，小组件颜值直接决定口碑图。
8. **空态与首启引导已经不错，可再补一步**：引导第 2 屏直接给「从 WakeUp/超级课程表导入」和「教务导入（内测）」两个按钮，把迁移成本前置到第一次打开。
9. **"点了没反应"零容忍**（G-05）：设置页占位项建议统一加 `规划中` 徽标，测试把"所有可见入口必须有反馈"列为走查项。
10. **保持我们的强项并放大**：液态玻璃、片段级自定义时间、冲突检测、导入数据钳制、响应式宽屏、电子宠物——这些是竞品普遍没有或不完整的，应在商店截图与引导页前置展示。

## 4. 明确不建议借鉴的部分

| 竞品做法 | 为什么不建议 |
|---|---|
| 开屏 / 信息流广告、看广告解锁功能 | 用户最反感点，也是 WakeUp 评分崩塌的直接原因；与"本地优先"定位冲突 |
| 校园社交（校花校草榜、小纸条） | 隐私争议大、运营成本高，课表工具做社交极易稀释定位 |
| 拍照搜题等"学习辅导"扩张 | 包体从 5MB 涨到 30MB、口碑反噬的实证案例 |
| 强制注册 / 登录才能用 | 课表本质是行踪数据；我们"不注册可用"是差异化，应保持 |
| 云同步默认开启 | 保持默认关闭、显式授权，符合我们隐私承诺 |

### 7.1 顺带修掉的两个门禁级缺陷

本轮开工前先跑基线，发现发布门禁实际是**红的**，与 README 的「0 issues / 269 passed」描述不符：

1. **`GlassCapability` 让 appInit 测试必崩（高）**：`_systemWantsReducedMotion()` 直接取 `WidgetsBinding.instance`，而纯 Dart 单测不会初始化 WidgetsBinding，导致 `app_init_test.dart` 的 5 条用例全部抛 `Binding has not yet been initialized`。改为读 `PlatformDispatcher.instance.accessibilityFeatures`（语义等价、不依赖 binding）。修复后该文件全绿。
2. **`test/link_audit/io_link_test.dart` 2 处 lint**：`if (x != null) 'k': x` 未使用 null-aware element 语法，`flutter analyze` 因此恒为 2 issues。已改为 `'k': ?x`。
