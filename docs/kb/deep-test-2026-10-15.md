## 1. P0（发版前必须处理）

### F-01 时间炸弹测试：门禁红，且 README 数字失真

- **现象**：`flutter test` 报 `+1337 -1`，失败用例 `test/presentation/calendar_makeup_badge_test.dart:96`「月历标出并念出补班日，且不吞掉『有课』」。
  实际读屏文本 `'10 月 10 日，无课，补班\n'`，断言期望含 `'有课'`。
- **根因**：测试把学期 `startDate` 设成「今天所在周的周一」（`:29`），而 10 月唯一补班日是 **2026-10-10（周六）**（`holiday_calendar.dart:171` 实锤）。10-11（周六）跑时「今天的周一」= 10-05，补班日落在第 1 周内 → 有课 → 绿；**10-12（周一）起跑时「今天的周一」≥ 10-12，补班日早于开学日** → 产品答「无课」是**正确行为**（那天还没开学），是**测试期望错了**。
- **加重情节**：这条用例自带「本月必须有补班日」守卫（`:42-48`），但没守卫「补班日必须落在学期内」。它是一颗按日历引爆的炸弹：10-11 当天验证通过、10-12 起天天红；2027 年起 1/4、2/14、2/28 等补班日同理会间歇性爆。
- **修法**：`startDate` 改为 `makeUps.first` 所在周的周一（或 `DateTime(month.year, month.month, 1)`），把「补班日在学期内」变成构造保证而不是运气。同时把 README「1322 全绿」改为重跑后的实数。
- **验收**：连续两天（跨过周一）跑同一用例都绿；`flutter test` 恢复 0 failed。

### F-02 重启手机后全部提醒静默丢失（B-06 未闭环）

- **证据**：
  - `android/app/src/main/AndroidManifest.xml` 全文无 `RECEIVE_BOOT_COMPLETED` 权限、无 BOOT receiver（只有 5 个 widget receiver，收 SCREEN_ON/TIME_TICK/DATE_CHANGED/TIME_SET——widget 有，**主 App 通知没有**）。
  - 通知走 `AlarmManager`（`flutter_local_notifications` 的 `zonedSchedule`），重启后系统不保留；重排唯一挂载点是前台壳 `main_shell.dart:157`（`ref.listen(rescheduleNotificationsProvider)`）。
- **后果**：用户重启手机 → 所有上课/DDL/考试提醒静默消失，直到下次手动打开 App 才恢复。没有任何提示。
- **加重情节**：课程提醒是 **6 周滚动窗口**（`notification_provider.dart:168` `_courseScheduleWeekWindow = 6`）。放假/实习 6 周以上的用户回来，第 7 周起提醒断档，也要等打开 App。参照物全部做了兜底：嘎嘎四类广播、Nexio 链式自注册、Dawn WorkManager 24h。
- **修法**：① manifest 加 `RECEIVE_BOOT_COMPLETED` + 一个 `BootReceiver`（BOOT / MY_PACKAGE_REPLACED / TIME_SET / TIMEZONE_CHANGED 四类）触发 Dart 侧重排入口（`MethodChannel` 或 `flutter_local_notifications` 的 background isolate）；② 把「为什么必须精确闹钟 + 为什么必须开机重排」写进代码注释（Nexio 的同款注释值得抄）。

### F-03 Android 13+ 拿不到精确闹钟权限，Doze 下提醒延迟

- **证据**：
  - `notification_provider.dart:417` 仍为 `AndroidScheduleMode.inexactAllowWhileIdle`。
  - 更有意思的是 `widget/KcbWidgetProvider.kt:117` 的注释自己写着「部分 ROM 禁 exact alarm（S+ 需 SCHEDULE_EXACT_ALARM 权限）」——**widget 侧知道要权限，manifest 里却没声明**，主 App 通知也照样用非精确模式。
- **后果**：息屏/Doze 下上课提醒可能延迟数分钟到数小时；Android 12+ 系统默认不授予 `SCHEDULE_EXACT_ALARM`，需要走 `canScheduleExactAlarms()` 探测 + 设置页引导（与既有 `battery_hint.dart` 同款「给步骤不擅自改系统设置」的产品口径一致）。
- **修法**：manifest 声明 `SCHEDULE_EXACT_ALARM`（明确不用 `USE_EXACT_ALARM`，注释写理由：后者是「闹钟类应用」权限、Play 审核会问）；排期改 `exactAndAllowWhileIdle`，探测失败时降级非精确并在设置页给引导；补「降级后仍能提醒」的正控用例。

## 2. P1（核心场景缺口，建议紧随 P0）

### F-04 微信/文件管理器收到的课表文件，无法「用其他应用打开」直达本 App

- **证据**：`AndroidManifest.xml` 的 intent-filter 只有 MAIN + `kechengbiao://` VIEW。无 `ACTION_SEND`/`ACTION_VIEW` + `text/calendar`、`.ics`、`.csv`、`.json`。
- **后果**：ICS 导入、CSV 导入的代码都在（`ics_import`、CSV 嗅探都已收口），但**用户手里有文件时没有路走进来**——WakeUp 文档的主路径恰恰是「在微信里打开 .ics」。功能在、门没有。
- **修法**：补 `ACTION_VIEW`/`ACTION_SEND` + 上述 mime/后缀；落到既有的导入预览安全边界（只产草稿、确认后写入）；iOS 侧同批补 `CFBundleDocumentTypes`/`Exported Type Identifiers`。

### F-05 教务导入引擎装配完毕但 catalog 恒空，开学录课痛点未解

- **证据**：`app_providers_data.dart:43-45` `academicAdapterCatalogProvider = const ScheduleAdapterCatalog.empty()`；`settings_page.dart:430-435` 读 `client.isEnabled` 展示「尚未接入」。引擎（~1150 行）+ `ScriptedAcademicImportClient` 全线就位，**零随包脚本、零学校索引、零登录 WebView**。
- **评价**：诚实占位比假功能好（竞品分析 §0 点名表扬过这个处理），但对开学季用户这是最大的空洞：四个参照物全都把「一键导课」当主战场，我们仍只能手动录或粘贴文本走 AI 识别。
- **修法**（低成本路线，竞品分析 G2-02 已给）：先做嘎嘎式三元组学校索引（校名/系统类型/URL）+ 10 条 URL 指纹，只有正方写专用接口、其余全走已有的通用 HTML 表格解析；登录 WebView 只在上边这条打通后再排。每步都可测（引擎已有 ~1150 行裸奔代码缺的只是锚点）。

### F-06 小组件数据契约死字段：Dart 写、Kotlin 不读

- **证据**：`widget_sync_provider.dart:138-139` 每次同步都写 `nextStartMinute`/`nextEndMinute`；对 `android/.../widget/` 全目录 grep，**五个 Provider + `WidgetData.kt` 零读取**（竞品分析 G2-06 2026-10-10 已记录，未清理）。
- **后果**：契约漂移的温床——下一个人改 widget 时会把这两个字段当「已接线」事实。要么用起来（到点自动切「下一节」），要么删掉，别留中间态。

## 3. P2（体验细节 / 工程卫生）

### F-07 全局搜索只搜当前学期

- **证据**：`global_search_page.dart:34` 数据源全部走 `currentTermIdProvider`。
- **场景**：复习季想找上学期某门课的老师/教室，或翻已归档学期——搜不到。建议加「搜索全部学期」档，或空结果时给一句「仅搜了当前学期，可从学期管理切换」。

### F-08 项目无版本控制

- **证据**：`D:\kechengbiao` 有 `.gitignore`/`.gitattributes` 但**无 `.git` 目录**，`git log` 报 not a repository。
- **风险**：47.8k 行代码 + 数据库迁移链（v1→v13）没有任何回滚点；README 的验收数字只能靠手写快照维护（这次「1322 全绿」失真就是直接后果）。建议 `git init` + 打基线 tag，哪怕只是本地仓库。

### F-09 鸿蒙端仍是非工程片段（已知账，复核确认）

- **证据**：`ohos/` 仅 6 个 `.ets`/`.json`，无 `module.json5`/`build-profile.json5`；通知走 `MissingPluginException` 降级 ⇒ 鸿蒙版不提醒。README §平台支持现状已如实标注，本项只作复核确认，不新增缺陷。
